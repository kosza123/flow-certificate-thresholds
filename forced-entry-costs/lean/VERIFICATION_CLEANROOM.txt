7. Limitations
--------------
- The run was made by the agent that assembled the project and wrote the nine Adapter modules,
  on the machine on which it was developed.  The directory, the Mathlib checkout and the
  download cache were fresh.  This is a reproduction record.  It is not an independent review of
  the mathematics, and it is not a review of whether the Lean definitions (`cost`,
  `adapterCost`, `IsWalk`, `pathCost`, `quadCost`, `dualRow`, `uRow`, `uCol`) say what the paper
  means.
- elan could not install the toolchain automatically in this environment: the release server
  that elan uses by default was not reachable.  The Lean 4.19.0 toolchain had therefore been
  installed beforehand from the official release archive on GitHub (lean-4.19.0-linux.tar.zst,
  sha256 6fe3ce97a58f44e2b3567d455b994eacec5bfe9ae7774f2a573444480ba813fe) and registered with
  elan by hand.  So the first step on an ordinary machine, where elan installs the toolchain
  named in `lean-toolchain`, was not exercised by this run.
- Mathlib is trusted as distributed.  It was not rebuilt from source: its compiled files were
  downloaded from the Mathlib cache.  lean4checker replays the twelve modules of this project in
  the kernel; it does not replay Mathlib (in particular not Mathlib's proof of the
  Birkhoff-von Neumann theorem, which is used through
  `exists_eq_sum_perm_of_mem_doublyStochastic`).
- The check says nothing about the parts of the paper that are not formalised; they are listed
  in README.md under "What is NOT proved here".
